## macOS 转换执行环境补充

- P34：macOS 26.5.1／LibreOffice 26.8.0.3 下，从受限代理沙箱启动 soffice 可能在 NSApplicationLoad → _RegisterApplication 路径 SIGABRT，或直接 exit 1 且无错误输出；`--version` 成功不能证明转换可用。2026-10-09 同机同实现的独立 profile、FONTCONFIG_FILE 真实转换测试在获准沙箱外执行后通过，实际服务无缓存中文预览也通过。开发代理应申请所需执行权限后启动服务与运行真实转换测试，普通终端可沿用 dev.sh／一键启动.command；保留独立 profile、字体配置与超时杀组，不改用共享 profile 或全局 kill，也不根据单次无 profile 成功就推断根因。未修改系统安全设置或安装其他转换器。
- P35：测试中重复调用 python-docx save 生成“相同内容”不保证 ZIP 字节相同（时间戳跨秒，见 P24）。导出同源字节断言必须复用传给渲染替身的那份 bytes，同时核对落盘与 HTTP 响应；不能再次生成文件作为期望值，也不能放宽字节一致断言。

## 页面边缘与校对补选

- P36：LibreOffice PDF 可能将顶部表格的文字块写在第一页正文末尾，PDF 内容流顺序不等于 DOCX 文档流顺序。只向前消费会漏掉联系方式，还会让末页段落与下一页续文被表格文字打断。定位优先顺序窗口、失败回查未消费行；只在完整文字拼接成功时消费命中行，重复正文不得重复使用同一行。跨页几何使用每页 fragments，顶层框保留首片段兼容旧结构，不能把不同页面坐标并成一个巨框；溢出高度按片段求和。自动框记录 geometry_version=2，升级后按版本失效重算，manual 框保护不覆盖。
- P37：未定位提示仅有文字、补选入口仅靠隐式拖拽，无法形成可操作的人工兜底。添加遗漏区域提供明确按钮与指引；未定位项直接重新框选已知区域，通过 PATCH bbox 保留 anchor／id／绑定，不依赖失败的自动反解。POST 框选命中已有 anchor 时复用区域，避免重复绑定目标；微调或再次框选某页保留其他页片段。切换模板／模式和取消操作清理草稿；新建仍限制一个区域一个段落，正文未识别短句也可框选创建。

新增经验请记录根因、触发条件、规避方法和验证依据；历史记录变更时保留替代关系。


## 全文识别与版本文字编辑补充

- P38：全文解析取消短句门槛后，历史模板不能直接删除区域并重建，否则人工排除、框和版本绑定会丢失。只追加旧规则漏掉的短句，按 anchor 去重、保持 id 和文档流顺序，并持久化一次性扫描标记；后续删除不能在重启时自动恢复。历史原件缺失或损坏时跳过升级，不阻断启动。迁移匹配矩阵测试应显式建立受控区域，不能再依赖“短文字没有候选”的旧行为。
- P39：直接修改已绑定字符块会影响所有引用它的版本。版本微调默认新建块（复制标签）并只换绑当前版本，只有显式同步才改共享原块；块变更和绑定必须同事务，保存失败不能遗留孤块。编辑窗口携带原文做冲突检查，占位符仅编辑替换部分，避免把段落前缀重复写进替换值。


- P40：原框坐标两位小数量化与 PDF 浮点基线可产生 ≤0.01pt 的高度差，不能当作真实溢出。测量先过滤该误差，裁剪仍强制警告；真实亚百分比增高保留小数，状态栏和区域共用格式函数，避免「+0%」。
- P41：词表扩充不能反向改变历史全文补齐的“过去忽略”判据。保存基础词表边界，只升级未校对、自动 custom 候选，以一次性 revision=3 保留人工状态／id／绑定和后续调整；同段多个占位符按 anchor+placeholder 分别匹配。正常模式的标题提示不能遮盖溢出／绑定说明。

## P42：版本段落删除与留白

段落删除记录归属内容版本，渲染前先解析全部元素引用，再物理移除；同段多个占位符一并隐藏，恢复清理同段删除记录。表格单元格最后一段删除后补合法空段，避免损坏 DOCX。空行块清空整段但保留 pPr；同步编辑空行块为文字时必须将 kind 切回 text，避免内容已保存但渲染仍留白。

## P43：撤销快照与渲染派生数据

自动 bbox／来源指纹和更新时间是派生数据，不应使撤销冲突；手工框必须纳入用户快照。恢复按外键顺序在单事务中完成，区域身份／绑定／标签一起恢复；模板文件不在撤销范围，模板结构变更清空日志。恢复前对当前语义状态做指纹校验，拒绝覆盖未记录的修改。

## P44：E2E 隔离与本地 PDF 字体

同秒生成相同 DOCX 会命中内容去重，fixture 应使用纳秒标记隔离场景。全文候选包含普通段落与 fixture 标记，校对回归不能只确认占位符。新版管理中创建版本后须明确点“使用”。未嵌入 CJK 字体需本地 cMapUrl/cMapPacked 和标准字体资源；修改 Vite 配置会重启，热重载时 worker 获取失败应与业务重载区别，刷新后验证正常。

- P45：LO 的整文档字体子集会随其他页内容改变，独立页 PDF 资源字节并不能代表该页可见内容。页级优化以原管线 PDF 的可见字形路径／图像与像素指纹为依据，注释／表单页保守回退；SVG 仅用于指纹，不用于预览。客户端校验 PDF sha 并限定同画布／尺寸／DPR；只有成功且仍为当前序号的渲染入缓存，取消／失败不得复用。API 参考：[PyMuPDF Page](https://pymupdf.readthedocs.io/en/latest/page.html)。


## P46 原生桌面服务与打包环境（2026-10-10）

- `Process` 直接运行 venv Python／Node，参数数组传递，避免 shell 路径空格和 TCC 归因问题；只保留并停止本实例创建的进程引用，复用不等于拥有，外部服务或部分启动失败不能误停已有进程。
- Vite localhost 可能仅监听 ::1，前端健康探测先尝试 IPv6 回环再尝试 IPv4；后端固定 127.0.0.1。健康响应校验 application 和项目真实路径 SHA-256，不能只看 HTTP 200。
- Foundation 的路径规范化可能隐藏 `/private/var` 别名，与 Python Path.resolve 不一致；项目身份使用 POSIX realpath，中文／空格及临时目录有生命周期回归。
- FileProvider 文稿目录可能立即重建 FinderInfo，导致 codesign 拒绝资源附加信息；在本地临时目录构建并签名，再复制普通文件内容并严格验签。只处理自产输出的 FinderInfo／ResourceFork，不移除 quarantine 或系统保护属性。
- 原生应用中文合成 PDF 默认文本提取受字体回退的内容流顺序影响；按页面阅读顺序 `get_text(sort=True)` 核对，并检查预览、导出及实际窗口，不能将提取顺序当作显示错误。

- 页级缓存真实 LO 测试必须使用临时 profile／缓存／字体配置，不能调用正式 get_manager() 与运行应用争抢同一 profile；进程内锁不保护跨进程并发。


## P47 模板字符块库与版本绑定不是同一关系（2026-10-10）

- 模板库使用独立成员关联，否则新建未绑定的块、解绑后的块会立刻消失；共享块保留同一身份，不通过复制内容制造分叉。
- 新成员表需纳入撤销快照依赖顺序，创建与关联同事务，绑定／迁移自动补齐目标成员，旧绑定幂等升级。模板删除只清理关联，全局块软删除规则保持。
- 当前模板切换清旧成员、选中块、筛选与编辑草稿；请求序号防旧响应覆盖，新建请求记录发起时模板，切换后不能选中旧模板新块。标签计数只按当前模板成员，窄屏抽屉未打开也应同步范围。

P46 补充：文稿目录中的 .app 即使构建后严格验签通过，实际启动仍可能被重新附加包根 FinderInfo；正式应用交付到个人 Applications 目录，启动后严格验签复核通过。应用运行测试副本只作验收，停止其服务后正常退出，正式应用重新启动并拥有两个服务。


## P48 · 独立窗口生命周期与 WebKit 导出

- LSUIElement／accessory 是菜单栏启动器行为；普通桌面应用使用 regular／非 LSUIElement，工作台作为主窗口。实现 applicationShouldHandleReopen，关窗后双击恢复；不要在服务就绪后调用外部浏览器代替主窗口。
- 原生编辑菜单不要截获工作台全局撤销快捷键：⌘Z／⌘⇧Z 留给既有网页历史处理，剪切／复制／粘贴沿用响应链。
- WKDownload 目标必须不存在。NSSavePanel 确认同名替换后，先下载到唯一同目录临时文件，完成时原子替换；失败保留旧文件。面板完成时目标不存在但下载结束前出现其他文件，禁止未经确认覆盖。保存／替换／取消／并发保护使用临时 fixture 测试。
- 更新应用前核实并正常退出旧进程，避免旧实例驻留造成启动无反应。桌面入口指向个人 Applications 的正式产物，不复制 FileProvider 目录中的开发包；服务仍仅停止本应用拥有的子进程。


## P49 · 标签界面精简后的过滤一致性

移除字符块库标签筛选入口时，列表不得继续读取历史 activeTagId，否则会留下无法清除的隐形筛选。只使用 matchesBlock 的统一查询，按名称／正文／标签搜索；换查询清空批量选择。移除管理界面不等于删除标签数据或接口，块编辑与共享必须保留标签。
