## 本轮确认范围（2026-10-19—20）

- 当前工作稿旁提供「归档」按钮，将此刻的 Word／PDF 保存为不可变记录；工作稿保留并继续编辑，不移动或删除来源。
- 归档形成独立「归档库」，支持搜索、只读查看、下载 Word／PDF 和显式删除；来源模板或版本删除后仍可使用归档。
- 移除应用内备份导出、备份校验与恢复功能，而非隐藏入口。保留磁盘上的已有备份文件，以及旧版数据迁移的内部一致性复制和空库保护。
- 缓存维护从服务状态的「预览维护」进入，不放在归档库。
- 用户要求精简页面顶部，避免块库展开后工具条复杂拥挤。顶栏默认「工作台／归档库／更多」，导入模板、模板制作指南、撤销／重做收纳到「更多」，保留快捷键；文档工具条保留块库、模板／内容版本选择、「管理」「归档」「导出」。导出仍为 DOCX，版本选项去掉重复绑定数量。
- 原顶部常驻缩放和图例改为画布底部「预览工具」折叠面板，保留绑定统计，默认折叠以减少常驻控件；选择器仅在画布容器 ≤560px 时另排一行，改善块库展开后的布局。
- 字符块库局部精简：标题集中当前模板范围、数量、新建与库操作，搜索保留一条；卡片编辑／删除收纳到更多菜单，正文最多展示三行、标签轻量显示，窄屏抽屉不重复标题。保留共享、批量、删除影响确认和既有 API，不将此局部调整扩大为素材模型重整。
- 以「检查可编辑区域」任务替代全局校对开关，文档底部直接提供「检查区域／添加区域」，自动切到模板原文并说明适用范围；候选逐项保留或忽略，可定位下一处、调整、删除及重新检查。完成后返回原内容版本并恢复缩放和滚动，已有校对结果保留。
- 补选直接框选一个段落，默认区域名可修改，类型按需展开；默认「保存并返回文档」，另可「保存并继续添加」，保存后不再重复确认。错误可重新框选并保留名称和类型；取消回到进入补选前的上下文，返回失败可重试。保留既有 API、数据结构、区域身份和绑定规则，不自动确认候选。

### 当前问题与边界

- 「内容版本」实际是可继续修改的内容组合，并不是历史快照；共享块更新还能改变多个版本。用“版本”同时暗示“不同用途的稿件”和“过去的记录”，容易误解。
- 归档与备份曾合用一个入口，混合了单份工作稿与整库维护。已确认收敛为「归档」与独立「归档库」，移除备份恢复；后续整体设计沿用此边界。
- 区域检查已改为明确任务并自动切换模板原文；导入引导与完整待处理问题列表仍需衔接，避免首次使用者自行寻找检查入口。
- 模板选择、版本管理、内容块库、正文微调和换模板迁移分布在不同面板，缺少围绕“一份文稿”的统一入口；独立归档库保留自己的查找职责。
- 正文微调默认隔离当前版本，但素材编辑默认更新共享引用；两种编辑入口看起来接近，影响范围却不同。

### 建议统一的对象

| 对象与简短说明 | 负责什么 | 现有能力如何承接 |
|---|---|---|
| 文稿：针对一种用途持续编辑的文档 | 选择模板、替换内容、局部修改、排版、导出 | 现有 version + bindings + 版本排版动作；不新建平行文稿表，不重编号旧记录，必要的行为增量见兼容表 |
| 模板：版式和可编辑区域 | 原 DOCX、区域识别／确认／排除／补选／微调 | 现有 template + regions，不承载某次投递的具体内容 |
| 素材：可以复用的文字内容 | 内容块、标签、搜索、模板库成员和引用关系 | 现有 blocks；“加入当前模板”与“用于当前文稿”分别表达，不混为绑定 |
| 归档：保存此刻的 Word 和 PDF | 搜索、查看、下载、显式删除，不随后续编辑改变 | 现有 archives；从当前工作稿归档，独立归档库管理，来源删除后仍保留（本轮已确认） |

“不同用途”建议用“另存为文稿”；“保存当时结果”按已确认名称使用“归档”。撤销／重做继续承担当前编辑会话的纠错，不再增加一个平行的“内容历史”入口。

归档和可编辑工作稿不合成一个冻结状态：同一工作稿可以继续修改并归档多次；来源删除后归档仍需可查。当前归档只有产物与来源描述，**不保证能完整恢复为可编辑工作稿**；“从归档继续编辑”若以后需要，必须单独设计并保存完整编辑快照和模板原件，不能用下载文件假装恢复。

### 前端组织与主路径

主导航建议为「文稿／模板／素材／归档库」，帮助与服务状态放入辅助菜单。首页默认文稿列表，名称旁显示所用模板，可搜索、继续编辑、另存和删除；不再先选模板才能寻找文稿。原型另提供“直接继续编辑”首页供比较，推荐列表起步，避免打开时误改上一次文稿。

首版不显示“最近编辑时间”：当前 versions.updated_at 只覆盖创建与重命名，绑定、排版及共享文字修改不一定更新它。若以后需要按最近编辑排序，须先定义并验证真实内容修改时间，不能将旧字段直接改标签。归档关联使用已有 source_version_id，来源不存在时仍显示独立归档，不能按名称猜测。

日常主路径建议为：选择或新建文稿 → 编辑文字／选用素材 → 查看实时预览与问题提示 → 导出或归档。已有模板可直接复用；首次导入模板进入区域检查引导。

编辑页建议：

- 顶部明确当前文稿名、所用模板和保存状态；主动作是“导出”，相邻提供已确认的“归档”。普通导出不自动制造归档记录。
- 宽屏默认只显示成品预览；点击正文后在旁边打开一个编辑面板，文字、选用素材和局部排版在此处完成。问题与视图工具按需展开，不同时常驻多个侧栏。窄屏采用同一上下文的抽屉，保持当前选区和未保存输入。
- 当前文稿可提供进入相关归档的快捷方式；归档库继续独立管理全部归档，包括来源已删除的记录，不要求先进入某份文稿。
- 选区点击直接进入文字或素材操作；删段、恢复段落、留白、前后插入、换行方式放在该区域的上下文操作中。缩放、图例放在预览视图工具中。
- “更换模板”明确展示匹配、无匹配和新增区域，先预览再生成使用新模板的文稿，保留原文稿。只是在模板库浏览或切换模板，不再自动触发迁移。
- 导出前汇总缺失绑定、溢出和当前区域问题，点击可定位；大超出仍按 D5 显式确认。普通信息不重复弹窗，错误在发生处解释并可重试。

### 五条操作路径与返回规则

| 任务 | 最短路径与明确按钮 | 取消、失败和适用范围 |
|---|---|---|
| 新建文稿 | 文稿 → 新建文稿 → 选已有模板或导入 → 命名 → 开始编辑 | 已有模板不强制重复检查；导入后提供“检查区域”和“稍后检查，开始编辑”。取消新建不产生空白文稿，已成功导入的模板保留在模板库 |
| 日常改稿 | 打开文稿 → 点击正文 → 输入文字或“选用素材” → 保存到当前文稿 | 默认不改其他文稿；未保存离开时保留输入或显式放弃。更新共享素材走独立确认，先展示真实引用影响 |
| 检查模板 | 文稿 → 检查区域 → 原模板与问题列表 → 完成，返回文稿 | 提示影响该模板所有文稿；逐项保存，可中断续作。添加区域直接框选，默认保存并返回，另有继续添加；回到原文稿、缩放和滚动 |
| 更换模板 | 当前文稿 → 更换模板 → 查看自动／候选／无匹配清单及目标新增区域 → 生成新文稿 | 推荐每次创建新文稿，原稿和目标模板已有文稿都保留；取消不写入。新稿名称冲突、区域变更或保存失败留在确认页并可重试，不悄悄丢弃未匹配内容 |
| 保存成品 | 当前文稿 → 归档 → 命名并保存 → 归档详情 | 保存独立 Word／PDF；原稿继续编辑。普通导出只下载 Word。删除来源不影响归档，归档删除单独确认；查看归档不进入编辑模式 |

模板库可独立导入和检查模板，不自动制造一份“默认文稿”；从模板卡片点击“用此模板新建”才创建文稿。该规则与当前实现不同，列入下方需确认项。

保存反馈与预览反馈分别表达：“内容已保存”不代表“新预览已就绪”。转换中保留旧预览，失败给出重试；保存失败保留输入，不能显示已保存。切换文稿／模板的旧响应不得覆盖新上下文。按钮忙碌时禁止重复提交，完成后恢复触发处或新页面标题附近的合理焦点；Escape 先关闭内层菜单，再处理外层抽屉。

文稿问题只汇总当前稿缺失绑定与溢出，并给模板问题入口；模板任务完整列出待检查、已排除、未定位、不可选，已排除是可查看的决定，不冒充错误。沿用 D5 的阻断与确认规则，不因整理界面新增导出门槛。

### 区域检查的后续衔接

本轮已实现检查与添加区域任务、直接入口和返回当前文档；以下导入引导、完整问题列表和页面组织仍为建议，不将整个 M39 视为完成。

- 导入后接续区域检查引导，展示待检查数量和下一步；沿用已有逐项保存与中断续作能力。
- 完整问题列表汇总待检查、已排除、未定位及不可选区域，定位到具体对象；与已实现的下一处检查、补选、调整、删除和重新检查衔接。
- 批量确认必须展示范围并由用户触发；不因置信度高就静默改变人工确认状态。
- 后续独立模板设置页与文稿编辑页进一步明确对象和返回路径，沿用模板本体与成品预览分工；内部 proofread 状态可继续复用。
- 日常编辑只提示相关待检查问题，不强迫每次导出都重走全部区域确认。哪些问题阻止导出沿用已确认规则；新增硬性阻断另行确认。

### 现有实现与兼容约束

2026-10-21 已核对模板上传、版本、迁移、正文编辑及归档实现。以下是接口设计方向，字段在对应实施模块落地前再做最小审查，不能仅改前端文案后宣称行为已改变。

| 项目 | 当前事实 | 推荐增量及旧数据兼容 |
|---|---|---|
| 文稿身份与列表 | versions.id 全局唯一；列表按模板获取，名称只在模板内唯一 | 前端显示“文稿”，保留版本 API、ID 与数据库名；首版聚合现有列表并携带模板上下文，不改旧名称。数据规模证明有需要时才增加全库摘要接口 |
| 模板与默认文稿 | 上传自动创建默认版本；删除最后一个版本会报 LAST_VERSION；模板预览已有无版本回退路径 | 新 UI 导入仅保存模板，模板允许零文稿。上传增加可选 create_default_version=false，旧调用默认 true；最后文稿删除采用显式允许空模板的 opt-in，旧调用继续保留原校验。旧默认文稿全部保留，不按名字或绑定数自动清理 |
| 更换模板目标 | 当前 plan/apply 使用目标模板最早的空白默认版本；默认版本已有绑定就报 MIGRATION_TARGET_NOT_BLANK | 增加显式新文稿模式，plan 只计算，apply 同事务创建新版本并写映射；原模式和返回字段语义对旧调用保持。新模式在创建前没有目标版本 ID，前端不得伪造 ID。需有计划有效性检查和提交幂等键，失败回滚、重试不重复建稿 |
| 归档来源 | API 已返回 source_version_id，前端 Archive 类型尚未声明；产物独立保存，无来源级联删除 | 补齐前端类型，按已有 ID 筛选“此文稿的归档”；来源仍存在时才提供返回文稿。旧记录来源缺失则独立展示，无需新增来源 ID 或按名称回填 |
| 当前稿与共享素材 | 正文 text 接口默认 sync_block=false，复制独立块并重新绑定；有 expected_content 冲突检查 | 复用现有隔离行为，不新增所谓“私有文字表”。共享更新明确展示 usage 影响后执行；模板成员关系与文稿使用关系继续区分 |
| 排版、删除与恢复 | 排版动作和绑定属于版本；软删除、missing 绑定和撤销各有既定范围 | 收拢入口不改模型；保留留白、段落删除／恢复、前后插入、换行和批量影响确认。素材删除后的 missing 不被迁移或另存悄悄扩散 |

需确认的行为选择：采用“文稿”命名和四入口导航；模板允许独立存在且新导入不默认创建文稿；更换模板总是生成新稿并保留原稿。其余如备份移除、独立归档、单次补选默认返回等沿用既有确认，不重复征求授权。

### 实施顺序与验收

归档、维护、界面精简和区域检查任务按上述本轮确认范围实施；以下剩余整体重整仍为建议，待用户确认职责和交互后才实施，编号不表示已完成。每个模块先修 bug，再以类型检查、lint、相关测试和实际浏览器操作验收后进入下一个模块。

| 模块 | 最小交付 | 可验证标准 |
|---|---|---|
| M37 统一职责与交互原型 | 确认术语、完整功能映射、文稿／模板／归档库线框和关键状态 | 每项现有功能有唯一主入口；走通首次导入、日常改稿、换模板和归档下载；明确哪些 API／数据契约需新增 |
| M38 文稿入口与上下文统一 | 先列表与导航，再模板独立存放／新建，再显式更换模板创建新稿，最后串联已有归档来源；每步独立验证 | 旧资料库无需重建、旧默认稿保留；取消不建稿，更换模板不覆盖；来源删除后归档可下载；普通导出不增加归档 |
| M39 模板准备与问题定位 | 补齐导入引导与完整待处理问题列表，衔接已实现的区域检查任务 | 首次导入能接续检查；待检查、已排除、未定位与不可选范围可定位并解释，保留逐项保存与中断续作 |
| M40 素材与选区操作统一 | 素材选择／独立修改／共享更新职责统一；合并选区文字与排版操作 | 当前稿独立修改、共享同步、删除影响和撤销均符合原契约；保留搜索／标签／模板成员关系；无暗中覆盖 |
| M41 整体验收与分发衔接 | 全量回归、宽窄屏、键盘／焦点、真实模板场景和更新迁移验证 | 同源预览导出一致；至少 3–5 个脱敏真实模板人工比对；全流程不依赖记忆模式开关；两架构正式分发另满足签名与干净机器验收 |

M38 的最小顺序为：M38a 文稿视图模型与列表 → M38b 主导航和当前文稿上下文 → M38c 模板独立保存及显式新建 → M38d 更换模板新稿模式 → M38e 归档来源快捷关联。每一步先补相关缺陷，再完成类型、lint、相关测试及前端操作验证；不能把五步打包后才检查。M39、M40 继续各自按任务／选区边界小步推进。

优先复用当前模板／版本／绑定／归档 API，以前端视图模型组织文稿。新行为用兼容的显式模式承接，不直接重命名数据库。文稿身份与归档来源已有稳定 ID；“从归档继续编辑”另需完整快照，不在本轮实施。旧归档无法可靠关联时仍保留为独立记录。

整体重整的操作目标：打开文稿后直接点击正文编辑；从正文一处进入所需素材和局部排版；工作稿旁可归档，归档库可独立搜索、查看和下载；日常改稿导出流程无需切换校对开关。性能沿用 D12 的现行验收口径：2026-10-21 用户已按当前实测验收本轮优化，原一秒目标不再阻塞本期，继续保留真实测量、旧预览与等待反馈。
