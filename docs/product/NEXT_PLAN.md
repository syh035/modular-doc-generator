## 本轮确认范围（2026-10-19—20）

- 当前工作稿旁提供「归档」按钮，将此刻的 Word／PDF 保存为不可变记录；工作稿保留并继续编辑，不移动或删除来源。
- 归档形成独立「归档库」，支持搜索、只读查看、下载 Word／PDF 和显式删除；来源模板或版本删除后仍可使用归档。
- 移除应用内备份导出、备份校验与恢复功能，而非隐藏入口。保留磁盘上的已有备份文件，以及旧版数据迁移的内部一致性复制和空库保护。
- 缓存维护从服务状态的「预览维护」进入，不放在归档库。
- 用户要求精简页面顶部，避免块库展开后工具条复杂拥挤。顶栏默认「工作台／归档库／更多」，导入模板、模板制作指南、撤销／重做收纳到「更多」，保留快捷键；文档工具条保留块库、模板／内容版本选择、「管理」「归档」「导出」。导出仍为 DOCX，版本选项去掉重复绑定数量。
- 原顶部常驻缩放和图例改为画布底部「预览工具」折叠面板，保留绑定统计，默认折叠以减少常驻控件；选择器仅在画布容器 ≤560px 时另排一行，改善块库展开后的布局。
- 字符块库局部精简：标题集中当前模板范围、数量、新建与库操作，搜索保留一条；卡片编辑／删除收纳到更多菜单，正文最多展示三行、标签轻量显示，窄屏抽屉不重复标题。保留共享、批量、删除影响确认和既有 API，不将此局部调整扩大为素材模型重整。
- 以「检查可编辑区域」任务替代全局校对开关，文档底部直接提供「检查区域／添加区域」，自动切到模板原文并说明适用范围；候选逐项保留或忽略，可定位下一处、调整、删除及重新检查。完成后返回原内容版本并恢复缩放和滚动，已有校对结果保留。
- 补选直接框选一个段落，默认区域名可修改，类型按需展开；默认「保存并返回文档」，另可「保存并继续添加」，保存后不再重复确认。错误可重新框选并保留名称和类型；取消回到进入补选前的上下文，返回失败可重试。保留既有 API、数据结构、区域身份和绑定规则，不自动确认候选。
- 上述为本轮确认的局部流程；下文的「文稿」命名、整体主导航、导入引导及完整问题列表仍为建议，未经确认不随本轮实施。

## 功能与界面整理建议（待确认，尚未实施）

目标：功能完整、职责清晰、易理解、易操作、说明简短明确。先收敛对象和主路径，再整理前端入口；保留本地离线、现有数据和单渲染管线。

### 当前问题与边界

- 「内容版本」实际是可继续修改的内容组合，并不是历史快照；共享块更新还能改变多个版本。用“版本”同时暗示“不同用途的稿件”和“过去的记录”，容易误解。
- 归档与备份曾合用一个入口，混合了单份工作稿与整库维护。已确认收敛为「归档」与独立「归档库」，移除备份恢复；后续整体设计沿用此边界。
- 区域检查已改为明确任务并自动切换模板原文；导入引导与完整待处理问题列表仍需衔接，避免首次使用者自行寻找检查入口。
- 模板选择、版本管理、内容块库、正文微调和换模板迁移分布在不同面板，缺少围绕“一份文稿”的统一入口；独立归档库保留自己的查找职责。
- 正文微调默认隔离当前版本，但素材编辑默认更新共享引用；两种编辑入口看起来接近，影响范围却不同。

### 建议统一的对象

| 对象与简短说明 | 负责什么 | 现有能力如何承接 |
|---|---|---|
| 文稿：针对一种用途持续编辑的文档 | 选择模板、替换内容、局部修改、排版、导出 | 现有 version + bindings + 版本排版动作，第一阶段只做前端组织与显示名称映射 |
| 模板：版式和可编辑区域 | 原 DOCX、区域识别／确认／排除／补选／微调 | 现有 template + regions，不承载某次投递的具体内容 |
| 素材：可以复用的文字内容 | 内容块、标签、搜索、模板库成员和引用关系 | 现有 blocks；“加入当前模板”与“用于当前文稿”分别表达，不混为绑定 |
| 归档：保存此刻的 Word 和 PDF | 搜索、查看、下载、显式删除，不随后续编辑改变 | 现有 archives；从当前工作稿归档，独立归档库管理，来源删除后仍保留（本轮已确认） |

“不同用途”建议用“另存为文稿”；“保存当时结果”按已确认名称使用“归档”。撤销／重做继续承担当前编辑会话的纠错，不再增加一个平行的“内容历史”入口。

归档和可编辑工作稿不合成一个冻结状态：同一工作稿可以继续修改并归档多次；来源删除后归档仍需可查。当前归档只有产物与来源描述，**不保证能完整恢复为可编辑工作稿**；“从归档继续编辑”若以后需要，必须单独设计并保存完整编辑快照和模板原件，不能用下载文件假装恢复。

### 前端组织与主路径

主导航建议围绕「文稿／素材／模板」组织，并保留独立「归档库」入口；设置和帮助作为辅助入口。首页建议默认文稿列表，展示名称、模板、最近编辑时间和归档数量，可搜索、继续编辑、另存和删除。

日常主路径建议为：选择或新建文稿 → 编辑文字／选用素材 → 查看实时预览与问题提示 → 导出或归档。已有模板可直接复用；首次导入模板进入区域检查引导。

编辑页建议：

- 顶部明确当前文稿名、所用模板和保存状态；主动作是“导出”，相邻提供已确认的“归档”。普通导出不自动制造归档记录。
- 宽屏为内容／素材侧栏、成品预览、可折叠问题面板；窄屏使用同一上下文的抽屉，保持当前选区和编辑内容。
- 当前文稿可提供进入相关归档的快捷方式；归档库继续独立管理全部归档，包括来源已删除的记录，不要求先进入某份文稿。
- 选区点击直接进入文字或素材操作；删段、恢复段落、留白、前后插入、换行方式放在该区域的上下文操作中。缩放、图例放在预览视图工具中。
- “更换模板”明确展示匹配、无匹配和新增区域，先预览再生成使用新模板的文稿，保留原文稿。只是在模板库浏览或切换模板，不再自动触发迁移。
- 导出前汇总缺失绑定、溢出和当前区域问题，点击可定位；大超出仍按 D5 显式确认。普通信息不重复弹窗，错误在发生处解释并可重试。

### 区域检查的后续衔接

本轮已实现检查与添加区域任务、直接入口和返回当前文档；以下导入引导、完整问题列表和页面组织仍为建议，不将整个 M39 视为完成。

- 导入后接续区域检查引导，展示待检查数量和下一步；沿用已有逐项保存与中断续作能力。
- 完整问题列表汇总待检查、已排除、未定位及不可选区域，定位到具体对象；与已实现的下一处检查、补选、调整、删除和重新检查衔接。
- 批量确认必须展示范围并由用户触发；不因置信度高就静默改变人工确认状态。
- 后续独立模板设置页与文稿编辑页进一步明确对象和返回路径，沿用模板本体与成品预览分工；内部 proofread 状态可继续复用。
- 日常编辑只提示相关待检查问题，不强迫每次导出都重走全部区域确认。哪些问题阻止导出沿用已确认规则；新增硬性阻断另行确认。

### 实施顺序与验收

归档、维护、界面精简和区域检查任务按上述本轮确认范围实施；以下剩余整体重整仍为建议，待用户确认职责和交互后才实施，编号不表示已完成。每个模块先修 bug，再以类型检查、lint、相关测试和实际浏览器操作验收后进入下一个模块。

| 模块 | 最小交付 | 可验证标准 |
|---|---|---|
| M37 统一职责与交互原型 | 确认术语、完整功能映射、文稿／模板／归档库线框和关键状态 | 每项现有功能有唯一主入口；走通首次导入、日常改稿、换模板和归档下载；明确哪些 API／数据契约需新增 |
| M38 文稿入口与上下文统一 | 建议增加文稿列表和当前文稿上下文，串联现有独立归档库；保持维护入口分离 | 旧资料库无需重建；工作稿与归档可分别查找；改稿、删除来源、重开后归档仍可下载；普通导出不生成额外归档 |
| M39 模板准备与问题定位 | 补齐导入引导与完整待处理问题列表，衔接已实现的区域检查任务 | 首次导入能接续检查；待检查、已排除、未定位与不可选范围可定位并解释，保留逐项保存与中断续作 |
| M40 素材与选区操作统一 | 素材选择／独立修改／共享更新职责统一；合并选区文字与排版操作 | 当前稿独立修改、共享同步、删除影响和撤销均符合原契约；保留搜索／标签／模板成员关系；无暗中覆盖 |
| M41 整体验收与分发衔接 | 全量回归、宽窄屏、键盘／焦点、真实模板场景和更新迁移验证 | 同源预览导出一致；至少 3–5 个脱敏真实模板人工比对；全流程不依赖记忆模式开关；两架构正式分发另满足签名与干净机器验收 |

优先复用当前模板／版本／绑定／归档 API，以前端视图模型组织文稿。若文稿与归档快捷关联、独立文稿身份或继续编辑归档需要新增稳定标识／编辑快照，先给出兼容迁移方案，不能直接重命名数据库或按来源名称猜测关联；旧归档无法可靠关联时仍保留为独立记录。

整体重整的操作目标：打开文稿后直接点击正文编辑；从正文一处进入所需素材和局部排版；工作稿旁可归档，归档库可独立搜索、查看和下载；日常改稿导出流程无需切换校对开关。性能沿用 D12，区分真实冷转换与重复预览，不用命中缓存的时延冒称所有编辑均达标。

### 开源参考与取舍

以下为 2026-10-19 阅读官方仓库／文档后的参考，职责与入口方案是针对本项目的设计建议，并非这些项目提供的同一套实现。

- [Reactive Resume](https://github.com/reactive-resume/reactive-resume)：统一文档库、在页面上选中并编辑、实时预览、自动和命名版本。借鉴“围绕当前文档组织编辑与记录”；保留本项目任意 DOCX 模板和 LO 单渲染管线。
- [Joplin Note History](https://joplinapp.org/help/apps/note_history/)：从当前笔记查看历史，恢复时另存一份而不覆盖当前内容。借鉴来源与保留记录的关系；本项目归档采用独立库，尚不具备完整可编辑恢复快照。
- [Paperless-ngx 文档详情与文件版本](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/usage.md)：在单份文档详情中查看文件版本、切换预览及下载。借鉴文件记录的预览和下载组织；其 archive file 是文档转换产物，与本项目“人工归档当前工作稿”的含义不同，不照搬其管理功能。
