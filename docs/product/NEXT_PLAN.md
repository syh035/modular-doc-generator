### 当前问题与边界

- 「内容版本」实际是可继续修改的内容组合，并不是历史快照；共享块更新还能改变多个版本。用“版本”同时暗示“不同用途的稿件”和“过去的记录”，容易误解。
- 「冻结归档」保存不可变的 DOCX／PDF；「备份」保存整个资料库。底层职责不同，但现在同放“归档与备份”入口，混合了单份文档与系统维护两种操作。
- 「校对模式」处理的是模板的可替换区域，预览会从成品切回模板本体，并禁用版本切换和导出。名称像文字校对，真实作用却是模板设置；用户需要记住当前模式才能解释按钮状态。
- 模板选择、版本管理、内容块库、正文微调、换模板迁移和定稿记录分布在不同面板，缺少围绕“一份文稿”的统一入口。
- 正文微调默认隔离当前版本，但素材编辑默认更新共享引用；两种编辑入口看起来接近，影响范围却不同。

### 建议统一的对象

| 对象与简短说明 | 负责什么 | 现有能力如何承接 |
|---|---|---|
| 文稿：针对一种用途持续编辑的文档 | 选择模板、替换内容、局部修改、排版、导出 | 现有 version + bindings + 版本排版动作，第一阶段只做前端组织与显示名称映射 |
| 模板：版式和可编辑区域 | 原 DOCX、区域识别／确认／排除／补选／微调 | 现有 template + regions，不承载某次投递的具体内容 |
| 素材：可以复用的文字内容 | 内容块、标签、搜索、模板库成员和引用关系 | 现有 blocks；“加入当前模板”与“用于当前文稿”分别表达，不混为绑定 |
| 定稿：保存此刻的 Word 和 PDF | 查看、下载、显式删除，不随后续编辑改变 | 现有 archives；显示为文稿的“定稿记录”，另保留全局查找和无来源记录 |
| 资料库备份：恢复整个工具的数据 | 导出 ZIP、校验、恢复、下载恢复前备份 | 现有 maintenance，放入设置 |

“不同用途”用“另存为文稿”，“保存当时结果”用“保存定稿”，“恢复整个工具”用“恢复资料库”。撤销／重做继续承担当前编辑会话的纠错，不再增加一个平行的“内容历史”入口。

定稿和可编辑文稿不宜合成一个冻结状态：同一文稿可以继续修改并保存多次定稿；来源删除后定稿仍需可查。当前定稿只有产物与来源描述，**不保证能完整恢复为可编辑文稿**；“从定稿继续编辑”若以后需要，必须单独设计并保存完整编辑快照和模板原件，不能用下载文件假装恢复。

### 前端组织与主路径

主导航建议为「文稿／素材／模板」，设置和帮助作为辅助入口。首页默认文稿列表，展示名称、模板、最近编辑时间和定稿数量，可搜索、继续编辑、另存和删除。

日常主路径：选择或新建文稿 → 编辑文字／选用素材 → 查看实时预览与问题提示 → 导出，或保存定稿后导出。已有模板可直接复用；首次导入模板进入区域检查引导。

编辑页建议：

- 顶部明确当前文稿名、所用模板和保存状态；主动作是“导出”，相邻提供“保存定稿”。“保存定稿并导出”可作为组合动作，普通导出不自动制造记录。
- 宽屏为内容／素材侧栏、成品预览、可折叠问题面板；窄屏使用同一上下文的抽屉，保持当前选区和编辑内容。
- 当前文稿内提供“编辑／定稿记录”。全局文稿列表可切换“定稿”视图，承接来源已删除的定稿；全局备份不再占用文稿工具条。
- 选区点击直接进入文字或素材操作；删段、恢复段落、留白、前后插入、换行方式放在该区域的上下文操作中。缩放、图例放在预览视图工具中。
- “更换模板”明确展示匹配、无匹配和新增区域，先预览再生成使用新模板的文稿，保留原文稿。只是在模板库浏览或切换模板，不再自动触发迁移。
- 导出前汇总缺失绑定、溢出和当前区域问题，点击可定位；大超出仍按 D5 显式确认。普通信息不重复弹窗，错误在发生处解释并可重试。

### 校对从全局开关改为模板任务

将用户可见的“校对模式”改为“检查可编辑区域”。它属于模板准备流程，也可从文稿“模板设置”进入；进入时明确“正在设置模板，将影响使用此模板的文稿”，完成或返回后恢复原文稿、选区和缩放。

- 导入后自动识别，并展示“待检查 N 项”；已有确认结果落库，可随时中断继续。
- 问题列表定位到具体区域，保留确认、排除、补选、调整框、删除和重新打开。补选从缺失位置直接开始，不要求先找到全局模式开关。
- 批量确认必须展示范围并由用户触发；不因置信度高就静默改变人工确认状态。
- 模板编辑页使用模板本体，文稿编辑页始终使用成品预览，两个页面标题和返回路径说明对象。可保留内部 proofread 状态实现，前端不再要求用户操作该全局开关。
- 日常编辑只提示相关待检查问题，不强迫每次导出都重走全部区域确认。哪些问题阻止导出沿用已确认规则；新增硬性阻断另行确认。

### 实施顺序与验收

以下均为建议，待用户确认职责和交互后才实施；编号不表示已完成。每个模块先修 bug，再以类型检查、lint、相关测试和实际浏览器操作验收后进入下一个模块。

| 模块 | 最小交付 | 可验证标准 |
|---|---|---|
| M37 统一职责与交互原型 | 确认术语、完整功能映射、文稿／模板／定稿三张线框和关键状态 | 每项现有功能有唯一主入口；走通首次导入、日常改稿、换模板、定稿下载和恢复资料库；明确哪些 API／数据契约需新增 |
| M38 文稿入口与维护分离 | 文稿列表、当前文稿上下文；定稿记录归文稿，备份与缓存进入设置；保留无来源定稿视图 | 旧资料库无需重建；当前稿与定稿可分别查找；改稿、删除来源、重开后定稿仍可下载；普通导出不生成额外定稿 |
| M39 模板准备与问题定位 | 用模板任务取代全局校对开关；导入引导、待检查列表、原文稿返回 | 区域操作逐项保存；失败不关编辑层；返回不丢文稿／选区；待检查、已排除、未定位与不可选范围可解释 |
| M40 素材与选区操作统一 | 素材选择／独立修改／共享更新职责统一；合并选区文字与排版操作 | 当前稿独立修改、共享同步、删除影响和撤销均符合原契约；保留搜索／标签／模板成员关系；无暗中覆盖 |
| M41 整体验收与分发衔接 | 全量回归、宽窄屏、键盘／焦点、真实模板场景和更新迁移验证 | 同源预览导出一致；至少 3–5 个脱敏真实模板人工比对；全流程不依赖记忆模式开关；两架构正式分发另满足签名与干净机器验收 |

优先复用当前模板／版本／绑定／归档 API，以前端视图模型组织文稿。若定稿归属、独立文稿身份或继续编辑定稿需要新增稳定标识／编辑快照，先给出兼容迁移方案，不能直接重命名数据库或按来源名称猜测关联；旧定稿无法可靠关联时保留为独立记录。

可测的操作目标：打开文稿后直接点击正文编辑；从正文一处进入所需素材和局部排版；当前文稿内即可保存、查看和下载定稿；日常改稿导出流程无需切换校对开关或进入系统备份。性能沿用 D12，区分真实冷转换与重复预览，不用命中缓存的时延冒称所有编辑均达标。

### 开源参考与取舍

以下为 2026-10-19 阅读官方仓库／文档后的参考，职责与入口方案是针对本项目的设计建议，并非这些项目提供的同一套实现。

- [Reactive Resume](https://github.com/reactive-resume/reactive-resume)：统一文档库、在页面上选中并编辑、实时预览、自动和命名版本。借鉴“围绕当前文档组织编辑与记录”；保留本项目任意 DOCX 模板和 LO 单渲染管线。
- [Joplin Note History](https://joplinapp.org/help/apps/note_history/)：从当前笔记查看历史，恢复时另存一份而不覆盖当前内容。借鉴记录从属于内容、恢复避免无意覆盖；本项目当前定稿尚不具备完整可编辑恢复快照。
- [Paperless-ngx 文档详情与文件版本](https://github.com/paperless-ngx/paperless-ngx/blob/dev/docs/usage.md)：在单份文档详情中查看文件版本、切换预览及下载；[完整备份](https://docs.paperless-ngx.com/administration/#making-backups)属于管理操作。借鉴文档记录与系统维护的边界。其 archive file 是文档转换产物，与本项目“人工保存定稿”的含义不同。
