# 项目文档导航

本项目以内容块和 DOCX 模板绑定为核心。文档按产品、架构、开发分类；现状和未实施规划分开记录。

## 按问题查找

| 要了解什么 | 文档 | 信息职责 |
|------------|------|----------|
| 如何启动和使用 | [根 README](../README.md) | 使用入口与运行说明 |
| 开发必须遵守什么 | [AGENTS](../AGENTS.md) | 现行规则、D1—D13、约束和文档入口 |
| 初始需求是什么 | [原始 PRD](product/PRD.md) | v1 初始需求历史；后续决策通过引用补充 |
| 下期做什么 | [下期规划](product/NEXT_PLAN.md) | 下一阶段目标、范围与验收 |
| 现在怎样实现 | [架构总览](architecture/OVERVIEW.md) | 基于当前代码的组件、数据和渲染关系 |
| 怎样协作和验证 | [开发规范](development/WORKFLOW.md) | 工作流程、检查入口和交接 |

## 目录职责

- `product/`：原始产品需求与一份下期规划。
- `architecture/`：当前实现总览；实际架构变化后更新，必要时记录关键决策。
- `development/`：开发协作、质量验证、可复用经验，`history/` 保存开发历史。

测试、安全、运行、发布等信息按实际规模拆分，当前在根 README、开发规范与架构总览中提供入口。没有内容时不创建空目录或空模板。

## 维护原则

- 实际任务状态在 TODO 维护；下期规划只写下一阶段目标、范围和验收，不复制全部任务状态。
- 不逐轮保存讨论、候选方案、撤回建议或聊天问答。文档在实际实现或阶段进展发生变化时更新。
- 接口和模型细节引用代码；架构文档说明关系，不手工复制完整 API 定义。
- 旧需求、旧任务和经验保留原始记录；更改决策注明依据和替代关系，不删除历史来消除差异。
- 文档移动时更新入口与链接；旧 `docs/PRD.md` 保留为兼容跳转。
- `STATE.md` 是被 Git 忽略的本地交接，不作为其他机器必然可读的项目规范；长期知识进入版本化文档。
